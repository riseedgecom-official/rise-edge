# Developer notes for the Rise Edge rebuild (not shipped to the user)

Flat static ES modules, no build step. Firebase Auth + Firestore (Spark plan). GitHub Pages hosting.

## Files
- `lib-core.js` state `S`, helpers, `t()`, event helpers (`act/onInput/onChange/onSubmit`), router `go()`, page registry `page()`, `refresh()`, `addBN()`.
- `lib-idq.js` + `verify.html` the QR on the ID card is a link to verify.html with what is printed on the card (name, ID, class/subject, batch, session; never phones or blood group). `fitLink` drops batch, then class, then name until it fits one QR (versions 1-10). verify.html is a static page (no login, no database): it only shows what is in the link. If the academy phone changes, edit the two constants at the top of its script.
- `lib-mascot.js` the avatar on the sign-in / registration screens (`mascotHtml(mood)`, `mascot(state, holdMs)`, `armCelebration`/`celebration` for the happy moment after a good login); it listens to focus/input by itself. One picture per state, `av-<name>.webp` (idle = the round profile picture, the others 400x600): idle, think (Login ID box), hide (password box), angry (wrong ID/input), sad (login failed: ID exists, password refused), confused (not an ID at all, or Forgot password open), happy (good login / registration done). To change a picture upload a new file with the same name. Styles: "the avatar" in app.css.
- `lib-ui.js` icons + HTML builders (`card row btn chips field input select textarea tag notice empty meter ring donut stat avatar batchPicker`), dialogs (`modal ask info form askText toast`), full-screen documents (`showDoc closeDoc`).
- `lib-svc.js` data services (`loadCore reloadPeople recalcBatch getStats batchData createAccount resetPassword removeUser notify logAct sendMail putFile delFile downloadFile squarePhoto shrinkImage saveInst defaultFee ...`).
- `lib-stats.js` pure calculations (`calcBatch examRows grade feeFor paidIn feeMonths subjectsFor findBatch defaultBatches rollOf ...`).
- `lib-db.js` the ONLY file that talks to Firebase. `db.get/list/set/upd/add/del/newId/batch`, equality-only `list` filters `[field,"==",value]`.
- `app.js` shell + router + global actions (`nav menu lang logout doc-print doc-close pick-batch retry`). `pages-auth.js` signed-out screens.
- Page modules (`pages-*.js`) are loaded by app.js with dynamic import; one broken module does not stop the others.

## Writing a page
```js
import { page, act, ..., S, t, esc, addBN } from "./lib-core.js";
page("students", async (params) => `<html string>`, { title: "Students", after: async (params) => {/* optional, runs after the html is in the DOM */} });
act("stu-save", async (el, ev) => { ...; refresh(); });   // markup: <button data-act="stu-save" data-arg="...">  (read el.dataset.arg)
```
- `refresh()` redraws the current page (keeps scroll). `go("page", {k:v})` navigates (`#/page?k=v`, read in `params`).
- Action names must be globally unique: prefix with the page (`att-`, `hw-`, `ex-` ...).
- Buttons with `data-act` are auto-disabled while their async handler runs (add `data-free="1"` to opt out).
- Forms: `<form data-submit="name">` + `onSubmit("name", (btn, ev) => ...)`; read with `formData(btn.closest("form"))`.
- Inputs: `data-input="name"` -> `onInput`, selects: `data-change="name"` -> `onChange`.
- Errors thrown inside handlers are shown as a red toast (friendly Firebase messages). Use `toast(t("Saved"), "ok")` for success.
- Page-local UI state that must survive `refresh()`: `const st = pageState("att")` (object kept in `S.q`).
- ALL visible text goes through `t("English text")`; ALL dynamic text in HTML goes through `esc()`. Reuse exact English keys already in `lib-bn.js` where possible; add new Bangla strings with `addBN({...})` at the bottom of your module.
- Roles: `isAdmin()` (main admin), `isStaff()` (admin or co-admin), `isTeacher()` (plain teacher), `isStudent()`, `canPublish()`, `canFees()` (admin only; co-admins never see fees/salary). A co-admin is a teacher profile with `ca:true` and `S.me.co === true`.
- `S.B` batches I may see, `S.U` approved students I may see, `S.TC` approved teachers (staff only), `S.PEND` people waiting for approval (staff only), `S.bid` selected batch, `S.me` me, `S.pid` my profile id, `S.INST` institute settings. A student only has `S.B=[own batch]`.
- Starting a page: usually `${batchPicker()}` first (it renders a select that redraws the page on change) and `if (!S.bid) return empty(t("Add a batch first."))`.
- Daily Firestore quota is small (50k reads): NEVER read all students' documents from a student's phone; students read only their own docs, `bstat/{bid}` (everybody's numbers for the month, in ONE doc), and batch-wide docs (hw, files, routine, syllabus). Cache with `batchData(bid)`. After saving attendance / marks / homework / batch start date call `await recalcBatch(bid)` so `bstat/{bid}` stays right.
- Keep the old app's Firestore collection names and field shapes (the new `firestore.rules` is derived from the old rules). The one change: there is no per-student `stats` field any more; use `getStats(bid)` -> `{rows:{studentId:{ex,er,ov,or,p,a,hw}}}`.
- Printable things (report card, receipt, ID card, result poster): `showDoc(html)` (full screen, always light, Print / Save PDF button). Wrap the content in `<div class="paper">`.
- UI look: boxes with outlines (`.card`), semantic colours only (green = ok/paid/present, red = bad/due/absent, amber = waiting, gold = achievement, blue = neutral). Use the classes in `app.css` (read it before inventing new CSS). If a page needs extra CSS, append a clearly labelled block to the END of `app.css`, scoped with your own prefix (e.g. `.att-...`).
- Mobile first (360px wide). Tap targets at least 40px. Lists as `.list>.item`, answer-sheet rows `.omr` + `.bub`.

## Roll numbers are reused
- No counter any more (`cn/..` is unused; its rules are still there). `takenRolls()` = every `login/<roll>` doc + the loaded people; `nextFree(role, year, taken)` = the smallest number not taken (001 for teachers is skipped = admin). Delete a person and that number is free again.
- `removeUser(u)` deletes users/login/hist/reports, marks `map/<uid>` = `_` (the old login can't enter), then `purgeUserData(u)` removes the person's data collection by collection (pr/pi, pay, sf, rq, pf, nt to the person, sal, ms, fp/reg by roll, attendance A/E, exam marks, performance marks, reports, bstat rows, records rows, monthly top posters). Each collection is its own try/catch, so a co-admin (no fee rights) still deletes the person; only the main admin's delete can remove fee records.
- A browser cannot delete somebody else's Firebase Auth login. So a reused number gets a NEW address `roll.xxxx@rise.local` (4 chars a-z0-9); the `login/<roll>` doc (create-only, written FIRST = atomic claim) holds the address the person signs in with. `openLogin(roll, pw, fn, plainOnly)` tries the plain address first.
- firestore.rules MUST be republished for the alias address (`login` create and `users` self-create accept `roll([.][a-z0-9]{4})?@rise.local`). With the old rules the reuse silently degrades: `plainOnly` makes selfRegister skip to the smallest number that was never used.
- Tests: `flows.rollReuse`, `flows.rollReuseOldRules` (mock: `window.__auth`, `window.__oldRules`).

## Rules can be run now: test/rules-eval.mjs + test/rules.mjs
- The Firestore emulator cannot be downloaded here, so `test/rules-eval.mjs` is a small interpreter for the rules language subset that firestore.rules uses (functions, `?:`, `in`, `is`, `.get/.keys/.hasOnly/.matches/.lower/.size/.diff`, `exists/get` with `$()` paths, `&&`/`||` absorbing errors like Firestore). `test/rules.mjs` runs the REAL rule text against the documents the app writes (teacher adds a student: users + login, notices, reads) and against things that must be refused. Extend it when a rule changes. It does not check list-query constraints.
- New account page robustness (pages-people.js): the ID and password are shown FIRST (`showCreated`), the lists reload afterwards (a failing reload can no longer hide them). If the app.js online is older and does not know `#/created`, the same details come up as a full-screen overlay (`.cr-ov`) instead of being lost (test: `open(..., {oldApp: true})`).
- lib-svc.js `createAccount`: a failing step says what was being done, why and the Firebase code, e.g. "Saving the profile and the login lookup of REAS-2026-007 failed: ... [permission-denied]".


## Every read and write of the app checked against the real rules: `RULES=1`
- `RULES=1 node test/flows.mjs` and `RULES=1 node test/run.mjs` run the app against the mock database, but each get / list / set / update / delete / batch is first judged by the REAL `firestore.rules` (`canPath` in test/rules-eval.mjs) as the person who is signed in (while a new login is being made: as the NEW person). A refused operation throws `permission-denied` like the real database and is listed at the end ("REFUSED role op path xN"; details in `rules-denied.json` in the shots folder). Writes of a batch are judged against the documents as they were before the batch; the number of documents the rules read is counted (limit 10 / 20).
- A LIST is judged on a stand-in document made of the query's own `==` filters and without the document id (a rule that needs more than the query says is refused, as Firestore refuses such a query). `get` of a document that does not exist is judged with `resource` empty (so a rule that reads `resource.data` refuses it, as the real database does).
- The interpreter now also does one-line `match` blocks, sub-collections, the `{c}/{id}` wildcard block, `.split/.upper/.trim/.replace` and `diff().affectedKeys()`.
- First run of it found: the admin could not LIST `users/<id>/reports` and `users/<id>/hist` (the `{c}/{id}` block does not cover sub-collections), so deleting a person silently left his reports and history behind. Fixed in the rules (`allow read` for admin / co-admin, `delete` on hist).
- Adding a person has a time limit per step (`LIMITS.step` in lib-svc.js, 30 s): a write that cannot reach the server waits for ever instead of failing, so the Save button used to stay on "Saving..." with no ID. Now the red text says it is taking too long.

## Practice sets: the AI assistant for teachers and the Practice page for students (pages-practice.js, lib-practice.js, lib-ai.js `askStaffAI`)
- The idea (user: "AI 50% control korbe"): the AI only DRAFTS. A teacher / admin gives photos / a PDF / a text file (up to 4 files; photos shrunk to 1280 px JPEG in the phone) and / or a topic, picks MCQ / short questions / summary / solve; the AI answers JSON; the teacher edits and ticks "I have checked the questions and the answers" before it goes to a batch. Students solve it in Study > Practice; marks are NEVER added to the exams.
- Data: `ps/<timeId>` = one set for ONE batch `{bid, ti, sb, by, bn, d, u, nt, qs:[{id,q,o[2-4],a,e,h,ed?}], sq:[{id,q,a}], ai}` (a teacher who ticks two batches makes two sets); `pt/<setId>_<studentId>` = the student's latest try `{sid, qid, bid, a:{questionId:index}, n, t, k, fl:{questionId:true}}`. Scores are computed from the CURRENT answers of the set (scoreSet), so when a teacher fixes a wrong answer every try is re-scored. A report (`fl`) older than the question's `ed` (edit time) is ignored (setStats). Question ids stay the same when a set is edited; `ed` is set only on questions whose text, options, answer, why or how changed.
- Rules (stamp `v20261117` = `RULES_VER`; publish the WHOLE file): `ps` read by the students of the batch and the teachers of it; create by a teacher of the batch (`by == sid()`, `psOk`: keys hasOnly, title <= 120, notes <= 6000, qs <= 40, sq <= 30); update / delete only by the author (admin / co-admin through the wildcard); the batch and the author cannot be changed. `pt`: the doc id must be `<qid>_<own id>` (a student cannot write over another's try), `get` of his own id is allowed even when it does not exist yet; list queries need `sid ==` (student) or `qid ==` + `bid ==` (teacher). - Cleanup: `purgeUserData` wipes `pt` of a deleted student; `bat-del` (pages-people.js) deletes `ps` / `pt` of the batch; `ps-del` deletes the set and its tries in one batch write.
